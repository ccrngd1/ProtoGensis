# VerifyLoop Demo: Multi-Tenant Authentication

This demo shows how VerifyLoop prevents AI agents from generating insecure code by making security invariants physically unbreakable at compile time.

## Scenario

A multi-tenant SaaS API where database queries MUST go through:
1. Input validation
2. Authentication (valid session token)
3. Authorization (tenant access control)

## Demo Structure

```
demo/
├── verifyloop.spec.yaml        # The spec defining the auth chain
├── without-guards/             # Vulnerable code (compiles but insecure)
│   └── vulnerable-api.ts
└── with-guards/                # Protected code
    ├── bad-api.ts             # WRONG: skips auth (won't compile)
    ├── correct-api.ts         # CORRECT: follows chain (compiles)
    └── guards/                # Generated by VerifyLoop
        ├── multi-tenant-auth.d.ts
        ├── multi-tenant-auth.ts
        └── index.ts
```

## Walkthrough

### Step 1: The Spec

See `verifyloop.spec.yaml`. It defines a 4-step chain:

```
RawInput → ValidatedInput → AuthenticatedCtx → AuthorizedQuery
```

And protects functions:
- `dbQuery`
- `dbWrite`
- `dbDelete`

These functions can ONLY be called with `AuthorizedQuery` type.

### Step 2: Without Guards

In `without-guards/vulnerable-api.ts`, an AI agent generates code that:
- ✗ Skips input validation
- ✗ Skips authentication
- ✗ Skips authorization
- ✗ Queries database directly

**This code compiles and runs**, but exposes critical security vulnerabilities.

### Step 3: Generate Guards

```bash
cd demo/with-guards
verifyloop generate --spec ../verifyloop.spec.yaml --output ./guards
```

This creates:
- `guards/multi-tenant-auth.d.ts` - Type declarations with branded types
- `guards/multi-tenant-auth.ts` - Constructor stubs and protected functions

### Step 4: Implement Guard Logic

Fill in the constructor stubs in `guards/multi-tenant-auth.ts`:

```typescript
export function validateInput(input: RawInput): ValidatedInput {
  // Add schema validation, sanitization
  const data = input.data as { userId: string; action: string; resource: string };

  if (!data.userId || !data.action || !data.resource) {
    throw new Error('Invalid input');
  }

  return {
    userId: data.userId,
    action: data.action,
    resource: data.resource,
  } as ValidatedInput;
}

export function authenticate(input: ValidatedInput, token: string): AuthenticatedCtx {
  // Verify JWT token, check session
  if (!token || !verifyToken(token)) {
    throw new Error('Authentication failed');
  }

  return {
    ...input,
    sessionToken: token,
  } as AuthenticatedCtx;
}

// ... etc
```

### Step 5: Try the Wrong Way

In `bad-api.ts`, an AI agent tries to query the database directly:

```typescript
const userData = await dbQuery(req.body);
```

**TypeScript rejects this at compile time:**

```
Error: Argument of type 'unknown' is not assignable to parameter of type 'AuthorizedQuery'
```

### Step 6: The Only Way That Compiles

In `correct-api.ts`, the code properly chains through all steps:

```typescript
const rawInput = createRawInput(req.body);
const validatedInput = validateInput(rawInput);
const authenticatedCtx = authenticate(validatedInput, token);
const authorizedQuery = authorizeQuery(authenticatedCtx, tenantId);
const userData = await dbQuery(authorizedQuery);
```

**This compiles** because we've satisfied the type chain.

## Run the Verification Loop

```bash
# Check the bad code (will fail)
verifyloop check ./bad-api.ts --spec ../verifyloop.spec.yaml

# Output:
# ✗ Verification failed with 1 error(s):
#
# bad-api.ts:23
#   Invariant: multi-tenant-auth
#   Violation: Argument of type 'unknown' is not assignable to parameter of type 'AuthorizedQuery'
#   Hint: Use createRawInput(validateInput(authenticate(authorizeQuery(input)))) to construct AuthorizedQuery

# Check the correct code (will pass)
verifyloop check ./correct-api.ts --spec ../verifyloop.spec.yaml

# Output:
# ✓ Verification passed
```

## The Impact

**Without VerifyLoop:**
- AI agent generates insecure code
- Code review catches it (maybe)
- Runtime testing catches it (maybe)
- Production incident (definitely)

**With VerifyLoop:**
- AI agent generates insecure code
- **TypeScript rejects it at compile time**
- AI agent receives structured feedback
- AI agent self-corrects to secure implementation
- Security invariant is physically unbreakable

## Key Insight

The security rule is no longer "please remember to authenticate." It's now:

**"This code will not compile unless you authenticate."**

That's the difference between probabilistic and deterministic verification.
