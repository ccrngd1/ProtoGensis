# MemDoc

## TL;DR

> **MemDoc** is a reproducible benchmark harness for agent memory in which **the agent writes
> its own memory** across fresh sessions and is then probed on facts the environment can't
> reveal. It compares doc-driven memory (always-load and Operator-style catalog), Mem0-style
> extraction RAG, transcript grep, and a CABAL-style **hybrid** along three axes: **who writes
> memory and when**, **how it is read**, and **how big it has grown**. Cost is counted per model
> call from Bedrock usage fields, with prompt-cache splits, because where memory is injected
> decides what it costs. Hypotheses are preregistered and hash-locked. The headline demo runs
> offline; live accuracy results are **pending live run** until a committed run log exists.

| id | name | write policy | read policy | inject |
|---|---|---|---|---|
| a0 | none | none | none | none |
| astar | oracle | n/a | oracle | prefix |
| a1 | doc_full | foreground | always_load | prefix |
| a2 | doc_catalog | foreground | catalog | prefix |
| a3 | rag_naive (weak baseline) | background | similarity | tail |
| a4 | rag_extract | background | similarity | tail |
| a5 | hybrid_tiered | foreground | hybrid_search | prefix |
| a5bg | hybrid_tiered_bg | background | hybrid_search | prefix |
| a6 | transcript_grep | none | agent_search | none |

(Generated by `memdoc arms list --format md`; see `docs/ARMS.md`.)

Note on framing: **CABAL — the production system this benchmark is shaped after — is a tiered
hybrid, not doc-only.** It runs always-loaded docs *plus* hybrid vector+BM25 search over an
indexed episodic tier and a background consolidator. A5 models that layout; A1/A2 model only
its doc tier. Hypotheses H1–H7 are preregistered and hash-locked in
[PREREGISTRATION.md](PREREGISTRATION.md) before any run.

## Why This Exists

Kevin Liao's "Agents Don't Need Memory. They Need Documentation." (liao.gg, Oct 2026) argued
that snippet-RAG memory is flawed at the base and that agents should consult and update
structured Markdown instead. The Hacker News thread asked for evals. Liao's own repo (Operator
Memory, issue #48) says existing memory benchmarks can't test a system where the agent **does
work and then commits knowledge**, and that he couldn't afford long-horizon runs. We found no
prior controlled comparison in which the agent writes its own memory (as of 2026-10-09;
research §3.3): MemoryArena <!-- cite:2602.16313 --> has the multi-session task shape but no
doc arm; gbrain-evals Cat 40 has a Markdown+grep arm but a fixed corpus the agent never
writes. MemDoc is the harness for the benchmark Liao described: the agent writes its own
memory, and *who writes, when* is separated from *how it is read* and *how big the store is*.

## What It Does

- **9 arms behind one `MemoryBackend` interface** (7 MVP + 2 should-ship ablations): no
  memory, oracle ceiling, always-load docs, Operator-style catalog, naive RAG (labeled weak
  baseline), Mem0-style extraction RAG with supersession, a hybrid tier (budgeted core +
  episodic search), its background-writer ablation, and transcript grep.
- **40 cross-session storylines** (8 categories × 5), seeded and validated: every probe runs
  in a fresh context, gold canary values are non-recoverable from the task environment, and
  unknown-unknown probes share zero content keywords with their fact text.
- **Store size as a controlled variable:** distractor sessions fill the store to ≈5K / 25K /
  100K tokens (±15%, measured and reported).
- **Exact cost accounting:** per-call usage fields × a dated pricing table, cached and
  uncached side by side, cache hit %, $ per successful task — never per-task token totals.
- **A deterministic cache simulator** reproduces Bedrock prefix-caching behavior offline, so
  the cache-placement result (head-injection busts history; tail and prefix cache well) is
  reproducible with no credentials.
- **A health gate** marks cells INVALID (excluded, counted, never scored as failures) when a
  retrieval path silently fell back — the gbrain lesson.
- **Preregistration:** H1–H7, the analysis plan, and the failure-cause taxonomy are
  hash-locked (`PREREG.lock`) before any run; `memdoc run` refuses to start if the hash
  doesn't verify.
- **A decay analyzer** (`memdoc decay`) measures exact-line survival of a memory file across
  its git history, printing aggregates only.
- **A reference workspace** (`memdoc reference init`): a synthetic hybrid-tiered template
  with a budgeted core, one-level catalog, and episodic notes.

## Why It Matters

The expected finding is a **crossover and a decision tree, not a winner**. Always-load docs
are cheap below the analytic break-even of 4,000 <!-- claim:breakeven-short --> / 6,000
<!-- claim:breakeven-medium --> / 9,000 <!-- claim:breakeven-long --> store tokens (short /
medium / long sessions, research §5.2 cost model, reproduced by `memdoc demo costmodel`), and
expensive past it; catalog reads stay flat; extraction RAG pays a per-turn floor; and
head-injected snippets re-write all history behind them on every turn — in the simulated
150-call session, head injection produces 6.9× <!-- claim:cache-head-ratio --> the
cacheWrite tokens of tail injection (baseline: A4 tail-inject, same session, simulated
cache). Where memory is injected decides what it costs. Accuracy claims wait for a live run:
**pending live run**.

## Install

Not published to any package registry. Install from the monorepo source:

```bash
git clone https://github.com/ccrngd1/ProtoGensis.git
cd ProtoGensis/mem-doc
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
source .venv/bin/activate
```

Core is stdlib-only. Optional extras: `[bedrock]` (boto3, live runs only),
`[vec]` (sqlite-vec, optional faster index).

## Quickstart (offline demos)

```bash
memdoc tasks validate          # storyline suite checks
memdoc prereg verify           # hash lock check
memdoc demo crossover          # headline mechanism demo (all arms x sizes x seeds)
memdoc demo cache              # head- vs tail-injection cache behavior
memdoc demo costmodel          # research §5.2 analytic tables + break-evens
memdoc demo stale              # the orders-service stale-ranking example
memdoc run --arms a0,astar,a1,a2,a4,a5,a6 --sizes 25000 --seeds 0 --out /tmp/md_run
memdoc report --runlog /tmp/md_run/runlog.jsonl
```

Every offline surface prints:
`MECHANISM DEMO: scripted agent, hashing embedder, simulated cache. Not benchmark results.`
Mock outputs are **context delivery (mechanism)** — what each memory layer hands the model —
never accuracy. Real-LLM behavior: not benchmarked; a budget-capped live mode exists
(`memdoc run --live bedrock --max-usd N`) but no live run has been made.

## Related work / prior art

- **Kevin Liao, Operator Memory** (BSD-3): the doc-driven thesis, the catalog/`read_if`
  format A2 adapts (attributed in `THIRD_PARTY_NOTICES.md`), and issue #48 asking for this
  benchmark.
- **MemoryArena** <!-- cite:2602.16313 -->: multi-session interdependent agentic tasks;
  closest academic prior art; no doc arm. We copy its SR@depth-k metric.
- **gbrain-evals Cat 40** (Garry Tan): Markdown+grep tied hybrid retrieval at the frontier at
  half the cost — and published two corrections after silent retrieval fallbacks, which is
  where our health gate comes from.
- **Letta's filesystem benchmark**: files + grep beat specialized memory tools on LoCoMo —
  with the caveat that Letta's filesystem also embeds (it is a hybrid, not pure files).

  (n=1, anecdotal).
- **calvinx / Astrocyte**: "documentation is memory with a different write policy" and "past

## Limits

- Storylines are **synthetic** and CABAL-shaped (agent ops, research handoffs, homelab
  config); no production data ships.
- Offline demos use a scripted agent, a hashing embedder, and a simulated cache: they show
  mechanism, not model competence. Offline similarity rankings are arbitrary with respect to
  semantics.
- The cache simulator's per-model minimums are unverified (`docs/CACHE_VALIDATION.md`); on
  the first live dry run, Bedrock usage fields win.
- A4 is Mem0-*style*, not Mem0; A2 adapts Operator's guidance but is not the real Operator
  harness (that arm, A7, is deferred).
- The decay analyzer measures exact-line churn, not wrong facts.
- One provider (Bedrock), pinned model IDs and dates; results may age as models improve at
  knowledge updates.
